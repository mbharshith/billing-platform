1. Overview

Type
Multi-tenant POS + storefront

Chain-wide topology (markets → brands → stores → outlets); operational data is outlet-scoped.

Persistence
Dexie / IndexedDB v9

Local-first. Schema v9 stamps outletId + [storeId+outletId] compound index on every tenant table.

Frontend
React 18 + Vite + TS

pnpm monorepo. No module federation - three apps compose via Vite aliases into packages/@billing/*.

Topology

markets, brands, outlets, stores, users, auditLog - chain-wide.

Outlet-scoped

38 tenant tables key on [storeId+outletId]. Each branch owns its own book.

Config

Menu, kitchen, recipes, warehouses, coupons - fanned per outlet on seed & migration.

Transactional

Sales, POs, GRNs, expenses, lending - backfilled to primary; new rows stamped by cashier context.

2. Data model (Dexie v9)

Every tenant table carries a compound key [storeId+outletId]. Outlet tables are cloned once per outlet on seed / migration; foreign-key columns (*Id) are rewritten with the same ::outletId suffix so references resolve inside a single outlet.

Fan-out illustrated

When a config row's outletId is not supplied, seed & migration clone it once per outlet of its store. Foreign-key *Id columns are suffixed the same way so references resolve inside the same outlet.

  id: "tbl-g-1",

  sectionId: "sec-ground",
  code: "T-01"
}

3. Architecture

apps/shell

Shell & router

Marketing home, tenant chooser, login, admin/cashier routing. Wraps <AuthProvider>. Alias-imports pos + storefront directly (no module federation).

apps/pos

POS + Admin

Cashier, live orders (kanban), KDS, dashboard, reports, 30+ CRUD admin pages built on useTable + CrudPage.

apps/storefront

Customer web

Browse, cart, checkout. Writes online orders via SalesContext.placeOnlineOrder(), stamps outletId.

Runtime layers

Route surface
/:slug/{admin,cashier} · /:slug/store/* · /login
React Router - one slug per store (velvet / spiceroute / lamaison)
Contexts (React)
AuthContext · SalesContext · ProductsContext · CustomersContext · UsersContext · StoresContext · SettingsContext · ToastContext · AuditContext
All read currentStoreId + currentOutletId from AuthContext to scope queries
Data hooks
useTable<Row>(name) · useLiveQuery
Auto-detects [storeId+outletId] index & filters live queries. Auto-stamps outletId on create().
Persistence
Dexie v9 · IndexedDB (browser)
Versioned schema (v1 → v9). bootstrapDb() seeds & fans out on first boot.

Package layout

apps/

  • shell - router + marketing + login
  • pos - cashier + admin (30+ CRUD pages)
  • storefront - customer-facing browse + checkout

packages/@billing/

  • shared - domain types, contexts, hooks, fixtures, Dexie
  • ui - atoms / molecules / organisms / feedback / admin / charts

4. Data flow

Read (any admin page)

  1. User logs in → AuthContext sets currentUser.
  2. readOutletFor(user) defaults currentOutletId to user.storeId (primary).
  3. User can switch via <OutletPicker /> - updates currentOutletId, persists in localStorage['active-outlet:<userId>'].
  4. Any admin page calls useTable<X>('tableName').
  5. Hook inspects Dexie schema, finds [storeId+outletId], runs db.X.where('[storeId+outletId]').equals([sid, oid]).
  6. Dexie's live query pushes updates whenever the underlying rows change.

Write (cashier records a sale)

  1. Cashier picks items, taps Charge → CashierCheckout modal opens.
  2. Selects order type / table / customer as needed.
  3. On confirm: SalesContext.recordSale(input) is called.
  4. Input is stamped: storeId = currentStoreId, outletId = currentOutletId, cashierId = currentUser.id.
  5. Invoice number is minted per outlet (outletSettings sequence).
  6. Dexie put in db.sales; live queries in Reports / Dashboard / LiveOrders update immediately.

Reading the diagram

  • Topology = chain-wide, never fanned per outlet (markets, brands, users, outlets themselves).
  • Outlet = keyed on [storeId+outletId]. Every branch has its own copy.
  • Config = seed / migration duplicates each row once per outlet so the branch launches with a full config.
  • Txn = new rows are stamped with the cashier's current outlet; historical rows were backfilled to primary.
  • PK = primary key. FK = foreign key. IX = indexed field.

Reading the code

  • packages/@billing/shared/src/lib/db.ts - Dexie schema v1 → v9 with upgrade functions.
  • packages/@billing/shared/src/lib/db-bootstrap.ts - fresh-install seed + fan-out helpers.
  • packages/@billing/shared/src/hooks/useTable.ts - the outlet-aware CRUD hook that powers every admin page.
  • packages/@billing/shared/src/store/* - one context per bounded aggregate.
  • packages/@billing/ui/src/admin/CrudPage.tsx - the DRY list + modal + confirm surface.
