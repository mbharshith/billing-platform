CRITICAL MOBILE Navigation
C-01 — Header navigation clips on mobile (390px)
Affects vendor + admin + cashier
Mobile 390×844 — only 'Overview' + partial 'Tenants' visible; Audit log, theme toggle, and user chip are all scrolled off screen.
What's broken

The header nav is a single horizontal row of pills. At mobile widths, the pills overflow horizontally without any visual indicator that more items exist. The theme toggle and user chip are entirely off-screen. Users physically cannot navigate to Audit log / log out on a phone.

How to reproduce
  1. Chromium DevTools -> device toolbar -> iPhone 14 (390×844)
  2. Sign in as vendor
  3. Observe header row
Recommended fix
  • Convert to bottom tab bar on <=768px — standard POS pattern (Square, Toast, Shopify POS)
  • Keep brand + user chip in top bar, move nav to sticky bottom
  • Or: hamburger menu -> sheet, but bottom tabs are ergonomically better for thumbs
CRITICAL TABLET MOBILE Cart
C-02 — Cart panel disappears below 1280px on /cashier
POS unusable on tablet
Desktop 1440px: cart on right
Tablet 768px: NO CART
Mobile 390px: NO CART

Product grid renders full-bleed on tablet/mobile but the ‘Current Sale’ cart panel is hidden entirely. A cashier tapping ‘Add’ on a product has no visible feedback and no way to review or check out.

Recommended fix
  • Below 1024px: cart becomes a bottom drawer that peeks (~80px visible with count + total) and expands on tap
  • Or: floating cart button (FAB) that opens a full-screen sheet
  • Both patterns are standard in mobile POS apps (Shopify POS, Square Register)
CRITICAL MOBILE Tables
C-03 — Data tables clip Actions column on mobile
Vendor tenants, sales, customers, products, users

Every table page relies on horizontal scroll to expose the Actions column. On the vendor Tenants page a mobile admin literally cannot Edit, Impersonate, or Suspend a tenant — the buttons are off-screen with no scroll affordance.

Recommended fix
  • Below 768px: swap table for a stacked card layout (one card per row, labels above values, actions in a row at the bottom)
  • Or at minimum: sticky-right column for Actions + gradient scroll hint on the edge
HIGH A11Y WCAG 2.5.5
H-01 — Header nav pills are 40×40 on mobile (below 44×44 touch target)

DOM measurement on mobile viewport shows every nav link renders at 40×40 px. WCAG 2.2 AA (2.5.5) requires 44×44. Also affects the Flipkart Bengaluru Central store selector (158×40).

Fix

Bump min-height / padding on the top-nav pills to 44px. Reserves comfortable tap area for thumbs.

.nav__pill { min-height: 44px; padding-block: 0.625rem; }
HIGH TABLET Discoverability
H-02 — Tablet nav is icon-only, no labels or tooltips

Between 768 and ~1100px the nav pills collapse to icons only. A cashier looking at "store / chart / receipt / user / bag" has to hover or guess which is Sales vs Products. Screen readers still work (aria-labels are present) but sighted users get zero affordance.

Fix
  • Either keep labels visible until they truly can't fit (dynamic breakpoints based on container query)
  • Or add explicit CSS title="Cashier" tooltip fallbacks
  • Bonus: highlight active tab more strongly (currently subtle background only)
HIGH MOBILE Cashier
H-03 — Category chips row overflows on cashier

Category filter shows All / Grocery / Produce / Beverages on mobile. Snacks / Household / Personal / Meat / Frozen are all clipped without a scroll indicator or wrap.

Fix

Either wrap chips (2 rows on mobile) or make the row horizontally scrollable with visible edge gradient + a "..." affordance.

HIGH Cross-viewport Cell wrap
H-04 — Tabular values wrap awkwardly (dates, phones, SKUs)
SKU 'ELE-\\n0001'
Phone '901-\\n234-\\n5678'
Date wrapping 3 lines

Values that should be single-token (SKUs, phone numbers, timestamps) wrap on hyphens and word boundaries when the column is narrow. Fix with white-space: nowrap + horizontal scroll on the row OR the card-per-row layout from C-03.

HIGH Consistency
H-05 — Edit is plain text link on /users, but a button everywhere else

On the Staff / Users page, "Edit" is a bare text link with no visual weight, but sits next to a proper "Deactivate" button. Mismatched affordance for equally-important actions.

Fix

Wrap Edit in the same Button variant="secondary" size="sm" as Deactivate. Consider adding an "edit" pencil icon for scanability.

MEDIUM × 6
M-01 through M-06 — Polish issues
  • M-01 — Store selector shows "Flipkart Be..." truncated. Add explicit title attribute + consider showing only the initials with a fuller label in the dropdown.
  • M-02 — "Frozen" category chip visibly clipped even on desktop. Either shrink typography or allow chip row to wrap after ~8 chips.
  • M-03 — Dotted underline hover cue on KPI values shows even when the value hasn't been compacted (e.g. "30", "8"). Only add the cue when compact != full.
  • M-04 — Filter chip counts (All 3, Active 3, Suspended 0) don't visually pop — consider inline badge styling with contrasting bg per state.
  • M-05 — Empty states are generic on many pages (Users has none at all). Standardize with icon + copy + primary CTA.
  • M-06 — Sales table's "CUSTOMER" column shows "—" (em-dash) for guest sales. Use "Guest" or "Walk-in" for clearer semantics.
LOW × 7
L-01 through L-07 — UX polish nice-to-haves
  • L-01 — Login page 'Demo tenants' block reads as monospace. Consider softening to sans + inline code chips for the credentials.
  • L-02 — Vendor console purple gradient is beautiful but slightly inconsistent with tenant's blue — consider a "role indicator" strip below the header on tenant views so context is unmistakable.
  • L-03 — Product cards on /cashier have wildly different tint backgrounds (blue, yellow, pink, tan) — delightful but random. Tie tint to category for visual grouping.
  • L-04 — "Impersonate" is a strong word. Consider "View as tenant" — less alarming for auditors reading logs.
  • L-05 — No breadcrumbs anywhere. Deep detail pages (Sale detail) leave user unsure of where they are.
  • L-06 — The QuickBill brand mark differs between vendor (shield) and tenant (spark) — intentional? If yes, document. If accidental, unify.
  • L-07 — No global search / cmd-K. For a POS with growing catalogs this becomes essential.

Senior UX review — heuristic evaluation (Nielsen 10)

1. Visibility of system status — STRONG. Toasts on save, active state on nav, live-updating tables. Missing on tablet/mobile cart adds.
2. Match system-real-world — GOOD. "Onboard tenant", "Impersonate", "Lending" all match retail vernacular. "Impersonate" could soften.
3. User control & freedom — PARTIAL. Cancel/close everywhere, but no undo on Suspend (only Reactivate). No back-button-safe modal history.
4. Consistency & standards — STRONG on desktop. Edit-as-link on /users breaks it. Vendor purple vs tenant blue is intentional and works.
5. Error prevention — EXCELLENT. Confirm dialogs for suspend, no-op detection on edit, 8-char password rule, duplicate-name inline error.
6. Recognition over recall — GOOD. Sidebar nav is stable, icons paired with labels (desktop). Tablet icons-only breaks this.
7. Flexibility & efficiency — WEAK. No keyboard shortcuts, no cmd-K search, no bulk actions on tables.
8. Aesthetic & minimalist design — STRONG. Whitespace, tabular-nums, subtle borders. Purple gradient brand marks are chef's kiss.
9. Help users recover from errors — GOOD. Toast copy is human ("This store has been suspended by the vendor"). Login errors surface inline.
10. Help & documentation — MISSING. No inline help, no docs, no first-time tour. Would land better with a subtle "Learn more" affordance on core pages.
